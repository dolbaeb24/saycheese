# Ролик от темы до файла

Ты ведёшь весь процесс сам. Другие скилы — это справочники по шагам: `reel-script`, `reel-voice`, `reel-hologram-hud` или `reel-three-table`, `reel-sound`, `reel-render-qa`.

## 0. Режим работы

- **По умолчанию** («сразу выдай готовый ролик»): никаких остановок, сразу делаешь и выдаёшь файл.
- **Поэтапный** (пользователь сказал «согласуй со мной текст, сюжет, сценарий, раскадровку»): после каждого этапа покажи результат и жди «да». Этапы: (1) текст и сюжет; (2) сценарий по формату «0:00–0:07 — голос — экран — что происходит»; (3) раскадровка — 6–9 настоящих кадров из сцены одним листом; (4) сборка без остановок.
- Если в окружении чего-то нет, сначала `reel-setup`.

## 1. Выбор стиля

| Тема | Стиль | Образец |
|---|---|---|
| Как устроено и работает устройство, механизм, процесс внутри предмета (микроволновка, климат машины, двигатель, холодильник) | `hologram-hud`: голографический каркас, рамки захвата, прокрутка цифр | `templates/hologram-hud-defog`, `templates/hologram-hud-microwave` |
| Математика, логика, алгоритм, «почему так» на простых предметах (принцип Дирихле, Shazam, вероятность) | `three-table`: тёмный стол, объёмные предметы, тёплый свет, подписи на предметах | `templates/three-table-dirichlet`, `templates/three-table-shazam` |
| Пользователь назвал другой стиль из библиотеки (watercolor, blueprint, iso-infographic и т. д.) | `$LIB/styles/<slug>/STYLE.md` — инварианты стиля; технику смотри в `demo/` после того, как написан сценарий | — |

Если пользователь просит предложить стили, покажи 3–10 вариантов из `$LIB/styles/README.md` с одной строкой «как это будет выглядеть в нашем ролике» и галерею https://lemomo-ai.github.io/lemo-opuscar/. Постеры стилей лежат в `$LIB/docs/frames/<slug>.jpg`, их можно собрать в один лист.

## 2. Проект

```sh
P=<workspace>/films/<name>            # имя: латиница, цифры, дефис
cp -r templates/<ближайший-образец> "$P" && rm -rf "$P/voice"/*.wav "$P/voice/words.json"
```

Из образца остаются движок, шрифты, `index.html`, `main.js`, `build.sh` (поменяй в нём имя выходного файла), `mix.py`, `sheet.py`. `film.js`, `models.js`, `cues.json`, `CREDITS.txt` и `tts_ru.py` (или `lines.json`) пишутся заново под тему.

## 3. Текст (`reel-script`)

Хук → механизм → что делать → вывод. 140–200 слов на 60–80 секунд. Факты проверены, оговорки есть. Текст для синтеза: числа словами, «ё», бренды по-русски.

## 4. Голос (`reel-voice`)

`lines.json` из 1–4 кусков → `tts_gemini.py` → `words.py` → проверка каждого слова → объект `K` с абсолютными временами ключевых слов (сдвиг голоса 0.30 с) → `CUES` → `DUR`.

## 5. Картинка (скил стиля)

1. Модели предметов (`models.js`) в единицах сцены, с подписанными частями: каждую часть, о которой говорит голос, можно захватить рамкой.
2. `film.js`: камеры по сценам, сцены как функции от `t`, выноски и карточки на временах `K`, список событий `EV`, субтитры `CUES`, HUD-рамка по безопасной зоне.
3. Сразу после первых сцен сними стоп-кадры и посмотри лист с рамкой безопасной зоны (`reel-render-qa`). Не пиши весь ролик вслепую.
4. Пройди проверку паузой по каждой фразе.

## 6. Звук (`reel-sound`)

`mix.py` по образцу: подложка, события из `EV`, непрерывный фон (вентилятор, гул), голос со сдвигом 0.30 с, приглушение. `cues.json` — экспорт `CUES`.

## 7. Сборка и проверка (`reel-render-qa`)

`build.sh` в фоне с логом, затем `qa.sh`. Исправь всё найденное за один раунд и проверь ещё раз.

## 8. Выдача

`deliver.sh` → `deliverables/`. Отчёт по-русски: первой строкой — где файл, длина и размер; потом по частям, что видно и что звучит; какие проверки прошли; оговорки по фактам; что посмотреть самому. Время по Алматы (UTC+5).

## Бюджет и порядок действий

- Озвучка — самый дефицитный ресурс (около 10 запросов в сутки). Не перегенерируй голос из-за ошибок распознавания: сначала `asr_crop.py`.
- Полный рендер дорогой (минуты). Все правки раскладки проверяй стоп-кадрами (доли секунды на кадр), а полный рендер запускай один раз, когда лист чистый.
- Ролик длиннее 90 секунд — только если пользователь просил.
